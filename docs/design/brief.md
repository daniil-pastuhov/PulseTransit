## Product
- What it is: live public-transport departure board for Norwegian stops (Entur) with MET Norway weather. Two modes: BOARD (always-on wall display) and ON_SPOT (follows the device).
- Users and context of use: (pending)
- Platforms / viewports: phone portrait, tablet / wall landscape, foldable / iPhone Duo, desktop window
- Themes: light + dark (Settings: System / Light / Dark / Auto by room light). Dark uses **OLED true-black** background with tinted cards; one dark theme.
- Accessibility target: WCAG 2.2 AA
- Implementation target: Compose Multiplatform (Android, desktop) with Material 3; SwiftUI (iOS 15+)

## Mood and brand
- Goal: **evolve** the current look (blue primary #1A73E8 / #5CA1FF, navy-tinted dark surfaces #0F1016/#161824/#1E2132, system font) — keep its character, add real type, a coherent token set and full state coverage.
- Feels like: **calm & legible** — station-signage clarity, big tabular numbers, quiet surfaces, colour only where it means something (lines, delays, now)
- Fixed brand assets: transport-mode line colours modelled on Norwegian operators (bus red #E74C3C, tram purple #7E48A2, train navy #003D82, express magenta #86005B, metro orange #C45B25, ferry teal #16A085, default grey #7F8C8D). **Keep the hues, tune lightness per theme** so pill text passes AA.
- References: (pending)
- Density: medium — wall board read from **1–2 m** (desk/kitchen), so denser rows and more stops per screen than a hallway sign
- Must not feel like: the Ruter/Entur apps, a generic Material template, flashy/gamey (gradients, glow, heavy motion), cold corporate dashboard
- Icons: one icon family for modes, weather and actions (replaces emoji); must have SF Symbols / Material counterparts
- Type: one bundled typeface with tabular figures, same on Android, iOS, widgets
- Current look observations: lavender route banner doesn't belong to the palette; amber/green weather temps low-contrast; weather hours truncated ("19:0"); emoji mode icons inconsistent across platforms

## Content
- Language / locale: English + Norwegian Bokmål; 24 h clock, Norwegian place names
- Voice and tone: plain and direct, second person, says what happened and what to do ("Could not find your location.", "Not now"). Mockups in English with Norwegian place names.
- Sample data domain: Oslo stops (Oslo S, Jernbanetorget, Majorstuen…), Ruter/Vy lines

## Scope
Board + on-spot (core, incl. detail sheets and route search), onboarding, settings, home-screen widgets.

## Key flows to make clickable
- First launch: mode selection → intro → board (empty) → Settings → add stop → choose directions → board
- Board → departure → details → filter out line
- Board → route banner → trip details → Notify me → rationale → following
- Search → place → results → trip details → save destination
- On-spot: change stop → back to nearest; locate → denied → allow

## State plan (phase 3)
Tiers per references/error-framework.md. ⚑ = judgment call, all three confirmed by the user 2026-11-12.

**Board (wall)** — Loaded · Loading (skeleton of header + 2 stop panels) · Empty first use: no stops ("Choose your stops" + Open Settings) · Stop with no departures ("No upcoming departures · Search further ahead") · Refreshing (thin bar, content stays) · Stale offline T4 ("No internet — shown data is 12 min old", role=status, under header) · Entur unreachable with cache T4 · Entur unreachable no cache T5 per panel (partial failure: one stop fails, others load) · Fastest route unavailable T4 inline in banner slot · No route by arrival time · Update available T4 banner (Update / Not now) · Paging (6 stops, "Stops 1–4 of 6", progress dots) · Dimmed (night, auto-dim) · Stress: long destination ("Filipstad via Aker brygge og Tjuvholmen"), 4-char line ("RE30", "FLY2"), cancelled, delayed +27, many departures, "+3 more" grouping, weather unavailable (strip hidden, layout closes gap). Viewports: phone, wall landscape, foldable (Duo bar header), desktop.
 ⚑ A failed background refresh while data is still fresh shows nothing (no snackbar on an unattended wall); it becomes T4 once data is older than 2 refresh intervals.

**Departure details (sheet)** — Loaded (later times + stop list) · Loading stop list (skeleton in list only) · Stop list unavailable (inline note, T4 in section) · Cancelled departure · After "Filter out line 31": sheet closes + T3 "Line 31 hidden · Undo" ⚑ (today there's no undo; it's reversible in Settings, so T3+Undo instead of a dialog).

**Trip details (sheet)** — Loaded (walk/ride/wait legs, stops collapsed) · Stops expanded · Direct vs 2 changes · Walk only · Following (progress, "Stop following") · Journey under way (riding, next stop) · Location lost during journey T4 ("Location off, following times only") · Notify flow → rationale.

**Route search (sheet)** — Empty (recent/saved destinations) · Typing with results · No places found · Results (alternatives) · Searching (skeleton rows) · No route to X T5-in-sheet · No route by arrival time · Offline T5-in-sheet · Travel time set ("Leave 08:15 tomorrow" chip) · Saved → T3 "Saved Majorstuen to destinations".

**Travel time picker** — Leave now · Depart at · Arrive by · tomorrow.

**Journey alerts rationale** — Android (time / location choice) · iOS (with time-limit caveat) · Notifications denied T4 with "Open settings".
**Notifications** — Departing · Next stop is yours · Change to · Walk · Faster route (Switch to it) · Missed ride · Arriving · Ongoing progress (Android notification + iOS Live Activity, lock screen).

**On-spot main** — Loaded (routes + nearest stop, divider) · Locating precise → approximate (skeletons + status) · Location denied T5 with "Allow location" · Location unavailable T5 + Retry · No stops within 1 km (empty in stop panel) · No destinations (empty routes: "Add a destination") · Other stop chosen ("Back to nearest") · Stop chooser sheet (nearby with distances) · Divider dragged to routes-only / departures-only · Offline stale T4 · Phone + foldable.

**Onboarding** — Mode selection (nothing selected / selected) · Intro: on-spot 3 steps, board 4 steps (step indicator, Skip/Next/Get started) · Location rationale + denied · Camera rationale (in Settings, wake by motion) + denied.

**Settings** — Main per mode (board / on-spot sections) · Stops: 0 / some / 6 (max reached hint) · Reorder mode · Remove stop → T3 Undo ⚑ (immediate, no confirm) · Location: not requested / requesting GPS / falling back to network / success / denied / failed · Manual coords field error T1 · Auto theme lux thresholds (live lux reading) · Camera sensitivity disabled until camera wake on.
**Add stop** — Nearby (loading/loaded/none nearby) · Search results · No stops found · Max 6 reached (Add disabled with reason).
**Stop directions** — All directions · Some selected · Quays loading / failed.
**Destination schedule** — Always · Weekdays 07–09 · Over midnight ("22:00–02:00 next day") · No days picked T1.
**Travel by** — All · some groups partly selected.
**Data sources** — Loading · Loaded (count) · Search no match · Load failed T5 + Retry.
**Journey alerts settings** — Time-only · With location · Some alert kinds off.

**Widgets (Android Glance; layouts reusable for WidgetKit)** — At a glance S/M/tall · Departures M/L · Fastest route S/M · Picker (choose stop / destination / nothing saved) · States: no stops, no destination, no origin, already at destination, no route, unreachable, "Offline · data from 08:12". Dark + light.

**Shell / global (page)** — Header variants (phone, wall, desktop, Duo vertical bar) · Settings navigation (Android full screen, iOS sheet) · Offline/stale banner behaviour · Update banner · Pixel-shift + dim illustrated · Error framework specimens.

## Implementation notes (visible-only, from the design)
- Widgets show clock times, not countdowns (they redraw every 15 min); realtime times get the accent colour and a dot.
- Widget design needs: a status field on GlanceView; RouteView legs as a list (for line pills) plus boarding time and platform as separate fields; weather/transport emoji replaced by bundled icons; the 2×2 glance layout redesigned (today's overflows).
- iOS widgets: 4×1 and 4×3 have no iOS home-screen size; iOS 15–16 widgets can't have a refresh button; the picker is Android-only.
- Settings: centred 640 px column from 700 px; from 1000 px board-mode settings split in two columns (what the board shows / how the device behaves). New group "Wake and dim" (camera wake, sensitivity, auto-dim) separate from OLED care. Location only in board mode. Mode switch is T6 in both directions. Schedule with no days is T1 only (one-screen form).
- Onboarding: no Continue button on mode selection; tapping a card proceeds.
